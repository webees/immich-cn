# 中国本地化

本项目的定位是**面向中国用户的 Immich 本地化项目**。目标不是复制某个数据包，而是围绕中国大陆用户的实际部署、显示、检索与数据质量，建立一条可验证、可自动更新、可追溯到来源的本地化链路。

## 本地化边界

- 本项目不维护 Immich 核心分支；Immich 文本目录与文件格式属于消费者适配层，规范数据模型仍以本项目的 SQLite 数据集为准。
- 默认输出简体中文；繁体可通过 `--chinese-variant hant` 生成，但地区用字仍以数据源与覆盖表为准。
- 中国地图瓦片、GCJ-02 坐标转换不修改 Immich 核心；本项目只说明影响并给出可选部署方案。
- 数据质量结论必须能由已发布制品、manifest 或独立复算复核，不能只靠项目介绍中的断言。

## 四个支柱与实测现状

| 层面 | 目标 | 当前证据 | 主要缺口 |
|:--|:--|:--|:--|
| 显示 | 中文地名，并按省/市/区县/乡镇逐级回退 | CN 34,897 条记录的展示名全部含中文（100%）；CN/HK/TW/MO 已在打包期做零缺失校验 | `{admin_3}` 只对 613 条 CN 点位改变展示名（1.8%），`{admin_4}` 只对 10 条改变（0.03%），离线数据大多止于市级 |
| 检索 | 中文、拼音、英文与繁体均可检索 | 已核对苏州市可命中 `Suzhou`、`Suzhou Shi`、`su zhou`、`蘇州`；中文在展示名，别名保留在 `cities500.txt` 第 3 列 | 检索质量取决于 GeoNames `alternateNamesV2` 覆盖率，项目尚未逐地名生成拼音 |

## 路线图

### 阶段 1：中文显示与检索（已完成）

- 中文展示名与 `{admin_1}` 到 `{admin_4}` 的回退、去重规则；
- `{admin_2}` 到 `{admin_2} {admin_3} {admin_4}` 的单一镜像粒度切换；
- 拼音、英文、繁体别名保留在第 3 列，由 Immich 的搜索索引消费；
- 每日自动检查上游，变化后自动构建、校验、发布 Release 与镜像。

### 阶段 2：部署与使用体验（进行中）

- 默认时区 `Asia/Shanghai`，并保留宿主机时区挂载的兼容写法；
- 说明国内网络环境下的镜像与 Release 验证方式，不以未经验证的第三方镜像替代官方来源；
- 说明 WGS-84 与 GCJ-02 的差异，给出底图选择建议；
- 把常见故障、升级与回滚步骤写入 [部署指南](deployment.md) 与 [常见问题](faq.md)。

### 阶段 3：行政区划补全（待办，先解决来源与许可）

当前最明显的短板是区县与乡镇层级。要把 GeoNames 点位映射到完整的省/市/区县/乡镇层级，必须先确认：

1. **数据来源与许可**：数据制品不适用 MIT；所选行政区划数据必须允许再分发，并明确署名与派生要求，见 [许可与署名](licensing.md)；
2. **匹配策略**：按行政代码、坐标、名称交叉匹配，冲突时保留来源并可回溯，禁止用人口或名称相似度静默覆盖；
3. **覆盖标准**：为每个省级地区设置覆盖率下限与抽样校验，至少包含一个已知边界点和一个人工复核点；
4. **负向控制**：破坏一条映射必须让校验失败，不能只用“总量增加”证明补全成功。

在这些条件满足前，项目不会把“全国四级行政区已完整”写成既成事实。离线数据继续回退，精确到乡镇可显式启用高德 provider，但高德结果是否可再分发由使用者自行确认。

### 阶段 4：地图瓦片与坐标（候选）

Immich 本身不做坐标系转换，其点位来自 GeoNames（WGS-84）。使用 OSM 等 WGS-84 底图时不存在系统性偏移；使用高德、腾讯等 GCJ-02 底图时，点位与底图可能出现约数百米偏移。该问题不能在 Immich 侧靠地名数据修复，只能通过选择 WGS-84 底图、在瓦片侧处理坐标，或引入独立的坐标转换层解决。

## 查询与检索的实际行为

| 输入 | 结果 |
|:--|:--|
| `苏州` | 命中苏州市 |
| `Suzhou` / `su zhou` | 命中苏州市（来自第 3 列别名） |
| `蘇州` | 命中苏州市（繁体别名同样在第 3 列） |
| `昆山` | 命中昆山市（区县层级记录） |

Immich 读取 `cities500.txt` 第 1 列作为展示名、第 3 列作为搜索别名，见上游 `server/src/repositories/map.repository.ts`。本项目把中文写入第 1、2 列，保留第 3 列为上游别名，因此中文显示与拼音/外文检索可以同时工作。

## 验收证据

每次发布至少应能回答以下问题：

- 数据来源是什么版本，源文件 SHA256 是什么；
- CN/HK/TW/MO 是否仍有展示名不含中文的记录；
- 当前 admin2/admin3/admin4 的覆盖数量与相对变化是什么；
- 14 个 Immich 变体和规范数据集是否通过结构、哈希与覆盖校验；
- Release、镜像 digest 与签名是否可以独立验证。

当前自动校验已覆盖前三项中的中文零缺失、文件结构与摘要；更高的层级覆盖率验收依赖阶段 3 的数据来源落地。
