# ADR 0001：规范数据集优先，Immich 输出仅作为适配器

- 状态：已接受
- 日期：2026-10-06
- 决策范围：数据格式、消费者兼容性、内部模型与发布方式

## 背景说明

Immich 直接从固定路径读取反向地理编码数据。文件名、制表符列位置、行政层级代码和 `geodata-date.txt` 的存在都是运行时契约。这个契约不是 immich-cn 定义的，也不能由发布方单方面改变。

但“需要兼容 Immich”不等于“项目必须沿用相同数据格式或使用方式”。如果让 Immich 的文本布局成为项目模型，查询、二次开发、来源追踪和其他消费者都会被这一兼容约定限制。

## 决策内容

1. 规范数据集是 `immich-cn-dataset-sqlite-v1.zip` 中的 SQLite 数据库，定义地点、国家、行政层级、四级中文名、来源和构建元数据；字段语义与结构版本由本项目维护。
2. `geodata*.zip` 是面向 Immich 的适配器输出，保持当前可读取的文件名、目录结构、列位置和语义，但不反向决定规范模型。
3. `levels.tsv`、`immich-cn-patterns-tsv-v1.gz`、`immich-cn-manifest-json-v1.json` 和提供方缓存是构建与适配中间层，可以独立重构。
4. 新消费者优先新增导出器；使用方式可以是 SQL 查询、CLI、镜像或未来的服务接口，不要求沿用 Immich 的目录挂载方式。

## 决策原因

- 规范模型可以让数据被直接查询、审计与二次开发，不必先接受 Immich 的列约定。
- Immich 兼容性仍被保留，但它是适配器能力，而不是项目身份或长期设计边界。
- schema 版本、来源哈希与制品指纹进入规范数据集，便于机器校验和自动化发布。
- 适配器边界明确后，规范模型与各个消费者可以分别演进。

## 预期结果

- `immich-cn-dataset-sqlite-v1.zip` 可用于 SQL、DuckDB、BI 或自定义程序。
- `immich-cn-geodata-admin2-default-v1.zip`、镜像中的 `geodata/` 以及 `data-*` 发布资产继续可直接使用。
- 规范字段变化必须提升 schema 版本并提供迁移方案；Immich 适配器仍需通过制品契约校验。

## 未选方案

### 仅保留文本格式

实现最省事，但会把一个外部消费者的列布局固化成整个项目的模型，无法自然支持查询、审计、增量分析和非 Immich 消费者，因此被拒绝。

### 用户自行转换

把规范化和兼容差异转嫁给用户，下载后还要自行解析列与层级，容易出现列错位、编码错误和版本漂移；发布规范数据集同时导出适配器更可验证。

### 并行多套格式

会造成多套事实源。只有在出现真实消费者并有兼容性与测试预算时，才从规范数据集增加新的适配器。
