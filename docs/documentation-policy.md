# 文档严谨性规范

文档必须区分事实、设计目标、运行条件、验证范围和未验证项，禁止把意图写成保证。

## 四类声明

| 类型 | 允许写法 | 禁止写法 |
|:--|:--|:--|
| 已验证事实 | 说明命令、版本、日期、范围与结果 | 只写“已验证”“保证正确” |
| 设计目标 | “按设计”“目标是”“默认路径下” | “完全自动”“永远不会失败” |
| 运行条件 | 明确前提、依赖和失败条件 | 省略 GitHub、上游、权限或网络前提 |
| 未验证项 | “未验证”“尚未覆盖”“需要实测” | 用推测代替证据 |

## 绝对化词语

“完全、任何、所有、永远、绝不、始终、唯一、保证、零风险、不会失败”等词只有在满足以下条件时才能使用：

1. 范围可枚举；
2. 验证方法可复现；
3. 例外条件已写出；
4. 不把策略承诺写成事实保证。

否则应改为带范围和例外的表述。

“全自动”在本仓库中作为机制名称使用，例如工作流徽章、章节标题和机制描述；
首次出现处必须写出运行前提（GitHub Actions、上游数据源、仓库权限正常），
不得改成“保证每天更新”。纯标识符（工作流 `name`、徽章文字）可保留简称。

## 独立性声明

“本项目不是重写、没有复用、不构成继承”这类说法描述的是**历史过程**与**法律状态**，
两者都无法从当前仓库的某一个提交中验证，因此不能作为事实写进文档。
关于独立性的表述只允许两类内容：

| 可以写 | 原因 |
|:--|:--|
| 当前树事实：在哪个提交、用哪条命令核查了哪些路径与关键词、得到什么结果 | 可复现，也可能被反例推翻 |
| 项目声明：本项目按什么方式组织代码与数据，并注明这是声明 | 读者知道它不是被证明的结论 |

| 禁止写 | 原因 |
|:--|:--|
| “完全独立”“没有任何复用”“从未移植”“不是重写版本” | 历史过程无法由当前树证明 |
| “不构成继承”“不侵犯著作权”“合法合规” | 属于法律结论，工程文档无权断言 |
| “只/仅在致谢中出现” | 需要穷举全部第三方关系才能成立 |

### 推荐模板

> 本项目按独立实现组织：本仓库当前树中的代码、配置、CI 工作流与数据构建脚本由本项目维护。
> 在文末「致谢」所列同类项目范围内，仓库路径名与生产代码中未发现被引用或打包的代码文件与人工整理数据文件
> （核查范围、关键词与命令见下文）。
> 文末「致谢」记录了与本项目相关的上游思路来源；Immich 文本格式兼容属于消费者接口适配。
> 以上描述的是当前仓库状态与项目声明，不是对历史过程或法律状态的结论。

### 不推荐写法

> 本项目是完全独立的实现，不是任何同类项目的重写版本，也不包含、改写或复用其代码与人工整理数据，
> 不构成代码、数据或格式继承。

逐条说明问题：

**“完全独立”“不是任何……重写版本”**：历史过程不可验证，且“任何”无法穷举。

**“不包含、改写或复用”**：即使拆开三种动作，也无法用当前树排除“复制后改写并删除痕迹”这类路径。

**“启发只在文末致谢中说明”**：只能描述当前树里相关引用出现的位置，不能断言第三方关系的全部范围。

**“不构成代码、数据或格式继承”**：这是法律判断；文档只能描述接口适配事实，
例如“本项目的 Immich 文本输出是消费者适配层，内部模型由 SQLite 规范数据集定义”。

### 核查方式

核查只回答“在给定提交、路径与关键词下是否命中”，不回答历史与法律问题。
核查对象是文末致谢中列出的同类项目，关键词取仓库名、作者名与派生写法：

```bash
git ls-tree -r --name-only HEAD | rg -i 'zinglix|geodata-cn'
git grep -n -i -e zinglix -e geodata-cn HEAD -- \
  src scripts docker config tests Makefile pyproject.toml
```

核查结果应写成“扫描范围为 X、关键词为 Y、结果未命中”，不能写成“绝无复用”。

### 核查记录

| 日期 | 范围 | 关键词 | 结果 |
|:--|:--|:--|:--|
| 2026-10-07 | `git ls-tree` 全树路径名 | `zinglix`、`geodata-cn` | 0 命中 |
| 2026-10-07 | 生产代码 `src`、`scripts`、`docker`、`config`、`tests`、`Makefile`、`pyproject.toml` | `zinglix`、`geodata-cn` | 仅命中本仓库的文档护栏与护栏测试 |

记录描述的是扫描时的工作树；提交锁定后仍应以该提交重跑命令为准。

## 特定领域

- **独立性**：只写当前树可核查事实与项目声明，不写历史过程断言或法律结论。
- **自动化**：说明触发条件、上游依赖、权限前提和失败路径，不写“保证更新”。
- **许可证**：说明许可范围和不适用范围，并注明内容不构成法律意见。
- **兼容性**：必须写明 Immich 版本、平台、路径和未覆盖版本。
- **安全**：必须写明扫描器、数据库/时间、扫描范围和例外，不写“无漏洞”。
- **数据质量**：必须写明抽样范围、阈值、上游覆盖和已知缺口，不写“全部正确”。
- **性能**：必须写明机器、数据规模、日期和测量方式。
