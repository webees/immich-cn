# 文档严谨性规范

文档必须区分事实、设计目标、运行条件、验证范围和未验证项，禁止把意图写成保证。

## 四类声明

| 类型 | 允许写法 | 禁止写法 |
|:--|:--|:--|
| 已验证事实 | 说明命令、版本、日期、范围与结果 | 只写“已验证”“保证正确” |
| 设计目标 | “按设计”“目标是”“默认路径下” | “完全自动”“永远不会失败” |
| 运行条件 | 明确前提、依赖和失败条件 | 省略 GitHub、上游、权限或网络前提 |
| 未验证项 | “未验证”“尚未覆盖”“需要实测” | 用推测代替证据 |

## 绝对化词语

“完全、任何、所有、永远、绝不、始终、唯一、保证、零风险、不会失败”等词只有在满足以下条件时才能使用：

1. 范围可枚举；
2. 验证方法可复现；
3. 例外条件已写出；
4. 不把策略承诺写成事实 guarantee。

否则应改为带范围和例外的表述。

## 特定领域

- **独立性**：只声明本仓库当前树中的依赖、代码和数据来源事实，不对第三方项目做法作出法律结论。
- **许可证**：说明许可范围和不适用范围，并注明内容不构成法律意见。
- **兼容性**：必须写明 Immich 版本、平台、路径和未覆盖版本。
- **安全**：必须写明扫描器、数据库/时间、扫描范围和例外，不写“无漏洞”。
- **数据质量**：必须写明抽样范围、阈值、上游覆盖和已知缺口，不写“全部正确”。
- **性能**：必须写明机器、数据规模、日期和测量方式。

## 项目独立性模板

推荐写法：

> 本仓库为独立实现。当前树中的代码、配置、流水线和构建脚本不依赖或打包同类项目的代码与人工整理数据，
> 也未从同类项目移植实现。存在的是思路层面的启发关系；Immich 文本格式兼容属于消费者接口适配。

不推荐写法：

> 本项目是完全独立的实现，不包含任何同类项目内容，也不构成任何格式继承。
